Aansluiten

Om aan te sluiten op de PRS of NVI heb je een PKIoverheid-clientcertificaat nodig. Hieronder lees je hoe je de aansluiting voorbereidt, je organisatie registreert en de verbinding test.

Aansluiten in vier stappen

  1. Zorg voor een PKIoverheid-clientcertificaat met de volledige certificaatketen en de bijbehorende private key.
  2. Registreer je organisatie en certificaat bij de beheerder van de dienst en stem de aansluitafspraken af.
  3. Test de mTLS-verbinding met de afgesproken serveradressen.
  4. Volg de OAuth-instructies voor PRS of NVI om een token op te halen en de dienst aan te roepen.

PKIoverheid-certificaat

Vraag een PKIoverheid-certificaat aan dat geschikt is voor clientauthenticatie. Met dit certificaat identificeert je client zich bij de PRS of NVI. Stem het te gebruiken certificaat en de registratievereisten vooraf af met de beheerder van de dienst.

Wat heb je nodig?

  • PKIoverheid-clientcertificaat met volledige certificaatketen (.crt of .pem)
  • Bijbehorende private key (.key)
  • Optioneel: PKCS#12-bundle (.pfx of .p12)

Meer informatie

  • PKIoverheid-combinatiecertificaten voor client- en serverauthenticatie
  • Organisaties die (gratis) testcertificaten aanbieden
Vereist PKIoverheid-certificaatprofiel

Type: G4 Private TLS Generic Devices Organization Validated Server (OID 2.16.528.1.1003.1.2.44.15.35.11). Dit profiel ondersteunt clientauthenticatie (clientAuth) en serverauthenticatie (serverAuth). De voorbeelden gebruiken het certificaat voor clientauthenticatie bij mTLS.

Organisatie-identificatie: Organisatie-identificatienummer (OIN).

Organisatie en certificaat registreren

Registreer je organisatie en het PKIoverheid-clientcertificaat dat je gebruikt vooraf bij de beheerder van de betreffende dienst. Stem daarbij de serveradressen en de benodigde toegangsrechten af. Rond deze registratie af voordat je een OAuth-token ophaalt of PRS/NVI aanroept.

Testdata

Gebruik uitsluitend testidentificatoren die via de aansluitafspraken beschikbaar zijn gesteld.

Verbinding testen met mTLS

Bij gewone TLS verifieert alleen de cliënt de server. Bij Mutual TLS (mTLS) verifieert ook de server de cliënt aan de hand van een clientcertificaat. Voor de aansluiting gebruik je hiervoor het PKIoverheid-clientcertificaat. Een verbinding zonder geldig clientcertificaat wordt op transportniveau geweigerd.

PKIoverheid-certificaat gebruiken

Gebruik voor de mTLS-verbinding je PKIoverheid-clientcertificaat met volledige certificaatketen en de bijbehorende private key. De bestandsnamen hieronder zijn voorbeelden; vervang ze door de paden naar je eigen bestanden:

  • client-cert.pem — je PKIoverheid-clientcertificaat inclusief de volledige certificaatketen.
  • client-key.pem — de bijbehorende private key.

Verbinding testen met curl

Test het OAuth-endpoint van de dienst waarmee je wilt verbinden. Vervang de URL-placeholders in de voorbeelden door de afgesproken serveradressen, inclusief https:// en zonder afsluitende slash. Gebruik voor de API en de OAuth-service het bijbehorende serveradres.

{{ range site.Data.services }} {{ $svc := . }} {{ with .oauth }}
{{ $svc.name }}
# Controleer of mTLS-handshake slaagt
curl -v \
  --cert client-cert.pem \
  --key  client-key.pem \
  "{{ .url_placeholder }}{{ .base_path }}/.well-known/oauth-authorization-server"
{{ end }} {{ end }}

Metadata en healthchecks

De metadata- en health-endpoints hieronder vereisen mTLS. Een OAuth-token is niet nodig. Gebruik je PKIoverheid-clientcertificaat en de bijbehorende private key om de verbinding te testen.

{{ range site.Data.services }} {{ $svc := . }} {{ with .oauth }}
{{ $svc.name }}
  • {{ .base_path }}/.well-known/oauth-authorization-server — OAuth-servermetadata
  • {{ .base_path }}/health — health check van de OAuth-service
  • {{ $svc.base_path }}/health — health check van de API
{{ end }} {{ end }}

Verbinding testen met een PKCS#12-bundle (.pfx / .p12)

{{ range site.Data.services }} {{ $svc := . }}
{{ $svc.name }}
# Controleer de mTLS-verbinding met een PKCS#12-bundle
curl "{{ $svc.url_placeholder }}{{ $svc.base_path }}/health" --cert-type P12 --cert "client.p12:<wachtwoord>"
{{ end }}

PKCS#12-bundle aanmaken

openssl pkcs12 -export \
  -in    client-cert.pem \
  -inkey client-key.pem \
  -out   client.p12 \
  -name  "gfmodules-client" \
  -passout pass:geheimwachtwoord
Beveilig je private key

Sla de private key nooit op in versiebeheer. Gebruik een secrets-manager (Vault, AWS Secrets Manager, Azure Key Vault) of een OS-sleutelketen.
